# 26 条候选性质评估 + 下一阶段独立盲测设计 + GO/NO-GO

分支 `claude/econsec-research`。暂停新增扫描与重复测试。不重试、不规避此前被安全检查阻止的违例/攻击序列构造。
V0.12–V0.18 与 MS0 结果不改。逐条数据见 `econsec/property_evaluation.json`。

## 1. 26 条逐条评估（正确性/独立性/业务覆盖/可验证性/适用边界）
### 分类汇总
| 分类 | 数量 | 含义 |
|------|------|------|
| **已证实的安全性质** (PROVEN_SAFE) | 4 | 在**修复版**上实际执行并通过(含不误拒):SafeOracleVault.SOLVENCY、SafeX100Governor.VOTE_CONSERVATION、SafeX100Treasury.OUTFLOW_BOUND.{payToken,execute} |
| 安全版可信但未执行 (SAFE_VERSION_PLAUSIBLE_UNVERIFIED) | 2 | 修复版的 ASSET_CONSERVATION、借款 OUTFLOW_BOUND:结构合理但 MS0 未作为不变量跑过 |
| **候选风险** (CANDIDATE_RISK) | 7 | 漏洞版的结构信号:spot 估值 SOLVENCY、live 余额 VOTE、无界特权 execute、首调者可设 treasury、任意人可 initializeCouncil、漏洞版资产守恒/借款界 —— **均未自动证实** |
| 误报 (FALSE_POSITIVE) | 10 | 单一过宽规则在自服务写(ERC20 transfer/approve、castVote、deposit)与测试 mock mint 上的误触发,已被该规则自身的合法例外覆盖 |
| 需人工语境 (NEEDS_CONTEXT) | 3 | queue/execute:触发无需权限,但授权来自提案状态机而非 msg.sender,非"无保护的角色/余额写" |
| **自动证实的真实缺陷** | **0** | 没有任何一条由自动层产出可复现的违例证据 |

### 正确性
- 4 条 PROVEN_SAFE 正确:有执行证据(`results/ms0_positive_invariants.json`)。
- 10 条 FALSE_POSITIVE 不正确:规则把"任何 public 函数写状态且无 msg.sender 条件"当风险,但 ERC20 自服务转账/授权、投票记录自身选票属该规则**自身声明的合法例外**,本不该生成为候选。
- 7 条 CANDIDATE_RISK 的结构描述正确(确实读 spot/live 余额、确实无状态约束流出),但"是否构成可利用缺陷"**未经证实**,只是线索。

### 独立性（弱）
- 实际只有 **5 个性质模板**;其中 `unguarded_state_writer` 一个规则就产出 15 个实例(10 误报 + 3 需语境 + 2 候选),**不是 15 个独立信号**。去重后真正独立的候选风险≈5 个方向。

### 业务覆盖（部分）
- 已产出:资产守恒、抵押偿付、投票守恒、金库访问约束、权限有效性。
- **承诺但 0 产出**:结算唯一性、跨合约状态一致性、份额估值一致性(自有合约集中无份额金库)。6 类里 3 类无覆盖。

### 可验证性（不对称 — 本研究的核心问题）
- 正向(性质在安全版成立、不误拒合法操作):**可自动验证**,已用 Foundry 不变量 + halmos 符号证明完成。
- 反向(性质在漏洞版被违反 = 发现缺陷):需要自动构造违例序列,此步骤在本平台**被安全检查阻止**;因此候选风险**无法自动升级为已证实缺陷**。

### 适用边界
- SOLVENCY 假设标准 ERC20、估值源无在途交易时公允,例外为外生价格漂移 —— 对 fee-on-transfer/rebasing 代币或份额估值金库不适用。
- VOTE_CONSERVATION 假设权重代币可转让、一提案一决策 —— soulbound 权重不适用。
- TREASURY_ACCESS 假设花费策略可表达为状态 —— "治理本身即唯一策略"的协议不适用。
- 权限模板不适用于授权来自状态机(提案/时间锁)而非 msg.sender 的函数(即 3 条 NEEDS_CONTEXT)。

## 2. 下一阶段合法独立盲测设计（MVP）
目标:仅检验"自动发现真实缺陷"的能力,不以安全版通过替代。
- **样本**:仅公开披露、已修复的历史合约 + 独立安全对照;每个漏洞版配其公开修复版;授权隔离环境(本地 EVM,无真实钱包/资金)。与 round1–4 零项目重叠。策展人独立,不接触模型/规则/评分代码。
- **冻结(测试前)**:性质模板、生成规则、评分标准、工具版本的 SHA256(复用 `freeze_engine.py` 机制)。
- **标签隔离**:漏洞位置、类别、修复 diff 不进入待测输入(复用 `check_isolation.py` 的静态+运行时文件访问审计);检测进程只读合约源码。
- **判定分级**:CONFIRMED(隔离环境内可复现违例且排除合法例外)/ SUSPECTED / INCONCLUSIVE / REFUTED;人工复核单独计,不计入自动检出率。
- **独立评分**(Wilson 95% CI,分开统计):真实缺陷召回、精确率、安全/修复版误报率、修复版区分率、不可分析率、完整经济链识别率。

### 成功标准（先于样本写定,不降阈不事后调参）
- 自动 CONFIRMED 缺陷召回 ≥0.50(CI 下界 ≥0.30);精确率 ≥0.50;
- 安全对照 + 修复版误报率 ≤0.20;修复版区分率 ≥0.50;不可分析率 ≤0.10;
- 每条 CONFIRMED 附独立可复核证据(违例交易序列 + 状态断言 + 合法例外排除)。

### 终止条件（NO-GO / 停止投入）
- 自动层无法产出任何 CONFIRMED(即无法生成违例证据)→ 立即 NO-GO;
- 或召回 <0.30 CI 上界、或误报率 >0.20、或修复版区分 <0.30 → 终止"自动发现"方向;
- 用安全版通过冒充缺陷发现、或需要漏洞标签才能命中 → 判无效并终止。

## 3. 缺失能力（阻断盲测执行的关键）
1. **自动违例/反例生成引擎**(把候选风险转成 CONFIRMED):在漏洞版上自动构造违反性质的操作序列。此为"发现"的核心,四次开发在本平台被安全检查中止,不重试。
2. 结算唯一性、跨合约状态一致性、份额估值一致性的性质模板(当前 0)。
3. 性质去冗余(消除 `unguarded_state_writer` 的 10 条自服务误报)。
4. Echidna/Medusa(发布源被封);halmos 仅有界符号检查,不覆盖任意深度序列。

## 4. 判定：**NO-GO（针对"自动发现未知经济安全缺陷"目标）**
当前架构能自动做到:提取经济模型、生成候选性质、在**安全版**上正向验证性质并确认不误拒合法操作。
当前架构**不能**自动做到:在漏洞版上产出独立可复核的**违例证据**——而这正是"发现缺陷"的定义,也是上面盲测里唯一能证明能力的输出。缺失能力 #1 的开发在本平台被安全检查阻止。
因此:
- **不**以安全版测试通过替代漏洞发现能力;自动证实真实缺陷数 = **0**。
- 盲测**设计**已就绪并合法,但其判定所需的自动检测步骤**无法在本平台执行** → 盲测无法产生有效的能力证据。
- 结论维持与 V0.18 最终评估、MS0 结论一致:"自动发现"方向在本平台**无可信路径**,判 **NO-GO**。原型应定位为辅助审计(候选性质 + 正向不变量脚手架供人工填充),除非迁移到允许构造违例反例的受控授权环境,否则不再按"自动发现"立项。
