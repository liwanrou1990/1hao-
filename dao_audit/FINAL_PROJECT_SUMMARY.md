## 3. 导致 NO-GO 的关键限制
1. **自动违例/反例生成引擎缺失**:将候选风险转为 CONFIRMED 缺陷需要在漏洞版上自动构造违反安全性质的操作序列。该模块开发在本平台被安全检查**多次阻止**;按要求不重试、不规避。缺此能力,"发现缺陷"的定义性输出无法产生。
2. **可验证性不对称**:正向(性质在安全版成立)可自动验证;反向(性质被违反)不能 —— 后者才是漏洞发现。
3. **历史证据一致**:四轮盲测的名称/模式匹配命中表现为开发集升、独立集落的过拟合;成熟静态分析(Slither 内置)对未知经济缺陷自动检出为 0。
4. **工具约束**:Echidna/Medusa 发布源被封;halmos 仅有界符号检查;历史依赖不可核验的项目只能 ANALYSIS_INCOMPLETE。

## 5. 重新立项的前置条件（技术 + 独立验收,全部满足方可）
**技术前置**
1. 受控授权环境,允许在隔离沙箱内对**自有或授权**合约构造违例反例(当前平台阻止,是 NO-GO 的根因)。
2. 可用的属性模糊/符号工具链(Echidna/Medusa 或等价 + halmos),覆盖多步操作序列。
3. 违例反例生成引擎:输出违例交易序列 + 状态断言 + 合法例外排除,人工可复核。
4. 补齐结算唯一性、跨合约一致性、份额估值一致性性质模板;消除 `unguarded_state_writer` 的自服务误报。

**独立验收(先于样本冻结,不降阈、不事后调参、不复用旧集)**
1. 新独立数据集:公开披露且已修复的历史合约 + 独立安全对照,与 round1–4/MS0 零项目重叠;策展人不接触模型/规则/评分。
2. 测试前冻结模型、规则、评分、工具版本的 SHA256;漏洞标签与修复 diff 隔离出待测输入。
3. 独立评分达标:自动 CONFIRMED 缺陷召回 ≥0.50(CI 下界 ≥0.30)、精确率 ≥0.50、安全/修复误报率 ≤0.20、
   修复版区分率 ≥0.50、不可分析率 ≤0.10;每条 CONFIRMED 附独立可复核证据。
4. 任一未达 → 维持辅助审计定位,不得宣称自动发现能力。

**边界(不变)**:仅自有/授权合约与隔离本地 EVM;不接真实钱包、不转移真实资金、不对未授权生产合约做主动验证;
真实发现走保密报告与负责任披露,不以未公开漏洞获利。
