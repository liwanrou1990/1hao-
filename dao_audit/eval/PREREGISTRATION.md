# 盲测预注册 (V0.12) — 真实历史合约 DAO 治理漏洞检测能力

> 本文件在**采集数据集与运行任何检测之前**写定并提交（见 git 历史：本文件的提交早于
> `eval/results/` 的任何提交）。冻结后不得修改通过标准、评分口径或引擎规则。
> 唯一目标：证明系统能否在**事先不知道漏洞位置与答案**的真实历史合约中，自动识别类似 X100 的
> 治理控制权失守与金库资金安全缺陷。

## 1. 完整性约束（硬性）

1. **引擎冻结**：`eval/freeze_engine.py` 记录检测引擎相关文件（`rules.py`、`static_scan.py`、
   `analysis/detectors.py`、`analysis/solmodel.py`）的 SHA256 与 git commit 到 `eval/engine_freeze.json`。
   盲测运行前校验哈希一致；盲测期间**不修改**任何检测规则/阈值。
2. **答案隔离**：待审计合约存于 `eval/dataset/<case>/contracts/`；标准答案存于 `eval/answers/<case>.json`，
   由独立评分器 `eval/evaluate.py` 保管。盲测 runner `eval/blind_run.py` **只读** `contracts/`，
   绝不读取 `answers/`、漏洞报告或修复说明。
3. **禁止泄漏**：runner 不得按项目名/地址直接匹配已知漏洞；按**项目**划分，同一项目的漏洞版与修复版
   为独立样本，引擎看不到标签。
4. **过程留痕**：runner 保存每个样本的原始检测输出到 `eval/results/raw/<case>.json`。
   评分仅在全部盲测输出产生**之后**由 `evaluate.py` 读取答案进行。
5. **人工发现单列**：任何需人工确认的发现单独列出，**不计入**自动检测成功率。
6. **数据集真实性**：仅收录有独立证据（源码 URL + git commit + 公开漏洞报告 + 修复证据）的真实历史案例；
   **禁止**使用本系统自写的 VulnX100Treasury / MiniDAO 等模拟合约；案例不足 10 个时**如实报告实际数量**，
   不用普通漏洞或人工植入漏洞填充。

## 2. 漏洞类别（与 X100 对应）

- **VULN-1** 治理席位异常接管：不合理席位获取 / 短期资产换长期治理权 / 初始化或权限验证缺陷。
- **VULN-2** 投票权异常：缺有效快照 / 临时借入资金影响投票 / 投票权重复计算或权重异常。
- **VULN-3** 治理提案执行缺陷：缺有效 Timelock / 权限刚变即可执行敏感提案 / 提案生命周期与执行权限缺陷。
- **VULN-4** 金库资金控制缺陷：过度授权的金库执行接口 / 提案可调用不受约束外部合约 / 缺关键资产转移与接收地址约束。
- **组合治理风险链**：上述多个缺陷是否可组成完整的“治理失守 → 资产损失”风险链。

## 3. 评分口径（每案，由 evaluate.py 自动计算）

对每个真实漏洞样本，答案给出：真实存在的 VULN 类别集合、每类的预期合约/函数（或行区间）、
是否构成完整风险链、关键治理权限关系、是否金库资金风险。评分：

- **是否自动发现**：引擎对该样本是否产出任一 finding。
- **类别正确**：引擎 finding 的 `rule_id` ∈ 答案的真实类别集合（逐类计 TP/FN）。
- **定位正确**：类别正确且 `contract` 匹配，且（`function` 匹配 或 `line` 落在预期区间 ±5 行内）。
- **治理权限关系/金库风险**：答案标注的关键关系是否被对应类别的 finding 覆盖（布尔，单列报告）。
- **误报 FP**：引擎在该样本上产出的、不属于答案真实类别/位置的 finding。
- **修复版误报**：在修复版/安全对照样本上，引擎是否仍产出 Critical/High 级治理 finding。

聚合指标（逐 VULN 类 + 总体），均给 **Wilson 95% 置信区间**：
- **Precision** = TP /(TP+FP)
- **Recall** = TP /(TP+FN)
- **FPR**（安全对照上）= 产生治理误报的安全样本数 / 安全样本总数
- **FNR** = 1 − Recall
- **完整治理风险链识别率** = 正确识别出 ≥2 个构成 takeover→treasury 链的缺陷（且含金库风险缺陷）的链式案例数 / 链式案例总数。**单独统计**，不以发现单一普通权限问题即算成功。

“定位正确”的 TP 才计入 Recall（仅“发现某处问题”但类别或位置错误不算该类 TP）。

## 4. 通过标准（冻结，先于结果写定）

设真实漏洞样本数 N_vuln、安全对照样本数 N_safe。

- **数据集充分性**：N_vuln ≥ 10 且含 ≥3 个完整风险链案例，才构成“结论性”测试；否则结果标注为
  **“探索性（样本不足）”**，不得宣称系统具备或不具备普适能力，只报实测数字。
- **判定“具备真实检测能力”(PASS) 需同时满足**（基于定位正确的 TP）：
  1. 总体 **Recall ≥ 0.70**（95% CI 下界 ≥ 0.50）；
  2. **完整治理风险链识别率 ≥ 0.50**；
  3. 安全对照 **FPR ≤ 0.30**。
- **判定“部分能力”(PARTIAL)**：满足上述 1–3 中的 1–2 项。
- **判定“不具备/未证明”(FAIL)**：三项都不满足。
- 无论判定如何，**不允许**用模拟合约的高成功率作为真实世界能力证明；最终结论只基于真实样本 + 独立评分。

## 5. 复测防过拟合（第二轮）

第一轮盲测原始结果 `eval/results/raw/` 与评分 `eval/results/round1_scored.json` 保留只增不改。
仅依据**漏报的技术原因**改进规则（记录每处改动理由），然后在**全新、独立**的案例集（round2，
与 round1 无项目重叠）上复测。禁止在 round1 集上反复调参后宣称盲测成功；round2 指标才是改进后的能力证据。

## 6. 安全边界（不变）

仅分析授权/公开历史合约；隔离本地 EVM 复现仅针对**已公开、已修复**的历史问题，用无价值测试资产；
不连接第三方真实金库、不执行未授权主网交易；保留 VULN-1..5、Foundry、Slither 及 DEX 监控全部功能。
