# 经济安全性质验证辅助审计原型 — 第一阶段设计（仅设计，不含漏洞发现）

本阶段**只交付设计**:架构、工具可用性、隔离测试方案、样本独立性方案、成本评估、GO/NO-GO 门槛。
不运行漏洞发现,不声称发现任何未知漏洞,不对未授权线上协议做任何验证,不绕过安全限制。
保留 DAO Audit V0.12–V0.18 与 MS0 全部归档与成绩,不修改历史报告。延续上一阶段结论:系统定位为**辅助审计原型**。

## 0. 与既有结论的关系（为什么这是"新原型"而非重启 NO-GO 方向）
上一阶段 NO-GO 的根因是:把候选风险升级为 CONFIRMED 需要**自动构造违例/攻击序列**,该步骤在本平台被反复阻止。
本设计**不**依赖"自动构造攻击序列"。它改用**性质验证**范式:Claude 提出候选经济性质 → 用授权环境内的
属性测试/符号工具去**验证或反驳**该性质;工具自身产生的反例是**工具输出的测试结果**,不是我们编写的攻击流程。
是否这一区别足以通过平台安全约束,是本阶段必须先回答的**可行性前提**(见 §6 风险 R1)——在它被确认前,不进入实现。

## 1. 目标与范围（最小可行,单一协议类别）
- 唯一协议类别:**ERC-4626 份额金库(tokenized vault)**。选它因为:核心经济不变量明确且与业务无关
  (份额-资产兑换单调、不可凭空增发购买力、存取往返不获利),历史上有大量公开披露并已修复的实现,
  且不涉及治理攻击序列。
- 不扩大到其它类别,不以规则数量充当能力。

## 2. 架构（P1 只设计，不实现）
```
[S1 构建]   授权合约 → 精确编译 + Slither IR            (复用 V0.15 compiler/*)
[S2 事实]   提取金库事实:资产代币、份额代币、totalAssets/totalSupply、deposit/mint/withdraw/redeem、
            预览函数、费用、外部依赖                      (复用 econsec/model.py 的事实层,不用名称匹配)
[S3 性质]   Claude 从事实 + ERC-4626 规范提出候选性质,每条产出:规范来源、合约位置、适用假设、
            合法例外、期望方向(must-hold / must-not)   (新;人类/规范驱动,非漏洞特征)
[S4 形式化] 把候选性质编译为:Foundry 不变量 handler + 断言;halmos check_ 函数(有界符号);
            (可选)Echidna/Medusa 属性                    (新;工具产生反例=测试结果)
[S5 验证]   在授权隔离环境运行。结果映射:
            REFUTED(工具给出反例且排除合法例外) / SUSPECTED(反例但例外未排除) /
            INCONCLUSIVE(不可达/超时/构建失败) / 正常业务通过
[S6 复核]   CONFIRMED 仅由独立人工复核在 REFUTED 证据上确认;人工层与自动层分开计分
[S7 评估]   冻结 → 独立盲测 → 独立评分(§4)
```
每条候选风险强制字段(§需求 6):规范来源、合约位置(file:line)、适用假设、验证结果、不确定性。
分级严格:SUSPECTED / INCONCLUSIVE / REFUTED / CONFIRMED(仅独立复核)。

## 3. 工具可用性检查（本环境实测，2026-11-01）
| 工具 | 状态 | 用途 | 备注 |
|------|------|------|------|
| Foundry 1.5.1(forge/anvil) | ✅ 可用 | 不变量模糊、隔离本地 EVM | vendored solc + solc-js shim 精确版本 |
| halmos 0.3.3 + z3 4.12.6 | ✅ 可用 | 有界符号验证(check_ 函数) | 仅有界;不覆盖任意深度序列 |
| Slither 0.11.6 / crytic-compile 0.4.2 | ✅ 可用 | S1/S2 事实提取 | 已在 V0.15–V0.18 使用 |
| Echidna | ❌ 不可用 | 属性模糊 | 无二进制;release 403;无 Haskell 工具链自建 |
| Medusa | ⚠️ 未确认 | 属性模糊(Go) | 无二进制;release 403;go 在场但拉取外部代码被环境限制拒绝(未自建) |
| Certora Prover | ❌ 不可用 | 形式化验证 | certora-cli 包可下载,但 certoraRun 需云端 prover + API key(外部服务),隔离环境不可用 |
**结论**:P1 可依赖 **Foundry + halmos + Slither**;Echidna/Certora 需外部资源,不纳入 MVP;Medusa 待确认(不阻塞)。

## 4. 独立盲测与评分方案（设计，先于样本冻结写定）
- **样本**:仅公开披露且**已修复**的 ERC-4626 金库历史实现 + 独立安全对照(审计过、无已知此类缺陷的金库)。
  每个漏洞版配其公开修复版。授权/公开来源,隔离本地 EVM,无真实钱包/资金/主网交互。
- **规模**:≥8 漏洞版、≥4 安全对照、每个漏洞版有修复版(ERC-4626 缺陷样本量有限,不足则如实报告为探索性)。
- **冻结**:S3 性质模板、S4 编译规则、评分标准、工具版本 SHA256(复用 `freeze_engine.py`)。
- **标签隔离**(复用 `check_isolation.py`):漏洞位置/类别/修复 diff 不进入 S1–S5 输入;静态检查(标识符不入引擎代码)
  + 运行时文件访问审计(验证进程只读合约源码)。
- **评分**(独立评分器,Wilson 95% CI,分开统计,人工复核不计入自动检出):
  真实缺陷召回、精确率、安全/修复版误报率、修复版区分率、不可分析率。

## 5. 样本独立性方案
- 策展人与引擎开发分离:策展人产出样本 + 隐藏答案,不接触 S3–S5 代码;引擎开发不接触答案/修复 diff。
- 与 round1–4、MS0 的 ERC-4626 相关样本(如有)零项目重叠。
- 开发集 vs 盲测集分离:P1 只用自有/少量开发样本调试 S3–S5;盲测集在冻结后一次性输入,不回流调参。

## 6. 成本与风险
- **一次性**:S2/S3/S4 原型(复用现有事实层),约中等;样本策展(人工,最大成本)。
- **每样本**:编译+Foundry 不变量(秒~分钟级)+ halmos(有界,分钟级);Claude 生成性质(每合约若干次调用)。
- **关键风险 R1(前置,阻塞)**:S4/S5 让工具对**漏洞版**产生反例,可能仍触发平台对"违例/攻击序列"的安全约束——
  这正是上一阶段 NO-GO 的根因。**P2 实现前必须先确认**:在授权自有合约上、由标准属性工具产生反例这一形式,
  是否可在本平台执行。若不可 → 维持辅助审计,不进入 P2。
- 风险 R2:ERC-4626 公开修复样本不足 → 结论只能探索性。
- 风险 R3:halmos 有界性 → 深序列缺陷可能 INCONCLUSIVE,不得记为安全。

## 7. GO / NO-GO 门槛（先于实现固定，不降阈、不事后调参、不复用旧集）
**进入 P2 实现的前置(全部满足)**:
- G0(前置)R1 得到确认:标准属性工具在授权自有合约上产生反例可在本平台执行。**未确认 → 直接 NO-GO,停在设计。**
- G1 工具链:Foundry + halmos 能在 ≥1 个自有 ERC-4626 安全版上跑通正向验证且不误拒合法操作(已有同类证据,MS0)。

**P2 盲测后判定"值得继续投资"(全部满足)**:
- 自动 REFUTED→独立 CONFIRMED 的真实缺陷召回 ≥0.50(CI 下界 ≥0.30);
- 精确率 ≥0.50;安全/修复版误报率 ≤0.20;修复版区分率 ≥0.50;不可分析率 ≤0.10;
- 每条 CONFIRMED 附独立可复核证据(工具反例 + 状态断言 + 合法例外排除 + 人工复核签字)。
**任一未达 → NO-GO**,维持辅助审计定位,不得以安全版通过或规则数量充当缺陷发现能力。

## 8. 本阶段不做
不实现 S3–S6、不跑盲测、不碰未授权合约、不构造攻击交易、不声称发现任何未知漏洞。
下一步需用户决策:是否先用**一个自有 ERC-4626 安全样本**做 G0/G1 前置确认(仍为正向验证 + 工具反例可行性探针),
再决定是否进入 P2。
