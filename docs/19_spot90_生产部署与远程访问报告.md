### 在你的 Mac 上实际上线（约 5 分钟）
```bash
git clone https://github.com/liwanrou1990/1hao- && cd 1hao- && git checkout claude/bgw-quant-v1
bash deploy/install_mac.sh                    # venv + 依赖 + launchd 两个任务 + 首次拉数 + 快照
curl -s http://127.0.0.1:8501/_stcore/health  # 期望 ok
launchctl print gui/$(id -u)/com.spot90.daily | grep -A6 calendar   # 确认每日任务已安装（08:40 / 12:10 本地时间）
launchctl kickstart gui/$(id -u)/com.spot90.daily && tail -5 logs/spot90_monitor/$(date -u +%F).log   # 手动触发一次并看日志
```
Linux 服务器：`bash deploy/install_linux.sh`（用户级，自动 `enable-linger`）或 `bash deploy/install_linux.sh --system`；验证 `systemctl --user list-timers | grep spot90`。

## 3. 每日自动更新状态
- 流程：`scripts/spot90_monitor_daily.sh` = ingest（Bitget V3 首选 → GitHub 公开 Binance 日线缓存）→ snapshot（参考价 + 新鲜度 + 指标 + 风险 + 成交概率 + 方案摘要）→ healthcheck（27 项 + Dashboard 探测 + 告警）。
- 调度：UTC 00:40 与 04:10 两次（备用源每日 03:17 UTC 发布前一 UTC 日的日线，第二次运行拿到最新日线；第一次运行会如实显示“日线延迟 1 天”）。本容器 00:20 UTC 的运行即显示“日线 2026-10-27，延迟 1 天”，页面同步给出“数据延迟，以上不是实时价”。
- 可靠性保障：`flock`/mkdir 并发锁（实测第二个实例以退出码 9 立即退出）；同一 UTC 日重复运行只覆盖当日快照（幂等）；快照/状态/健康结果/parquet 全部先写临时文件再 `os.replace`（原子）；日志按天保留 60 天；Webhook 地址只从 `~/.config/spot90/env` 读取，日志仅记录 `webhook configured: yes/no`（实测结果文件与日志中不含 Webhook URL）。
- 当前状态：本容器内**未安装**定时任务（没有可用的 cron/systemd/launchd）；安装脚本会在 Mac/服务器上真实安装并给出验证命令。

## 6. 重启恢复测试结果
便携守护 `deploy/run_dashboard_supervised.sh`：启动 → 健康 `ok` → `kill -9` Streamlit 进程 → 端口立即不可达 → **3 秒后自动恢复**（新 PID），守护日志记录 `exited rc=137, restart in 2s`；恢复后健康检查“Dashboard 进程健康 HTTP 200”，Playwright 3 轮 × 4 页签测试 0 异常。生产环境由 launchd `KeepAlive`（ThrottleInterval 10 秒）/ systemd `Restart=always, RestartSec=5` 提供同等能力；plist 已用 `plistlib` 校验、systemd 单元已核对关键字段，但**未在真实 macOS/Linux 服务管理器上执行**，首次安装后请用第 1 节命令验证。

## 8. 14 天限价成交模型的定位
页面已明确声明：相对“按折价档的历史成交率”这一简单统计基准没有显著优势（样本外 Brier 技能 +0.003，95% CI −0.03~+0.03），合并 AUC 0.78 几乎全部来自折价深度；它是校准良好的参考工具，不是经验证的 AI 交易优势，且成交概率 ≠ 盈利概率（成交后 90 天盈利率 56%~60%，与立即买入无异）。
