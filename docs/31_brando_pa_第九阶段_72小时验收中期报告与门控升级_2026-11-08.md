## 5. Mac 本地可执行命令（按顺序；不操作你的 Mac，由你执行）

```bash
cd ~/1hao-
git fetch origin claude/brando-pa-phase9-deploy
git show origin/claude/brando-pa-phase9-deploy:scripts/brando_pa_mac_upgrade_verified.sh > /tmp/brando_upgrade_verified.sh
BRANDO_REPO="$HOME/1hao-" BRANDO_LOCAL_START="2026-11-08 12:23:00" bash /tmp/brando_upgrade_verified.sh claude/brando-pa-phase9-deploy
```
脚本行为：
1. **预检**：fetch；打印 HEAD、origin、落后提交数；本地有未推送提交 → 停止；待应用提交若触碰 `config/brando_pa.yaml`、accounts、ledger、trend/risk layer、allocator、engine 或账户目录 → 停止（连 dry-run 都不跑）；记录三账户资金快照。已是最新 → 跳过升级，只做复核。
2. **dry-run**：调用 `brando_pa_safe_upgrade.sh --dry-run`（不停服务、不改代码）；读取 `upgrade_report_<UTC>.json` 做硬门控：`ok=true`、备份 `verified=true`、`fast_forward_possible=true`、无本地修改的非数据文件、演练期间账户快照 `diffs=[]`、新版本时间审计 returncode 0。任一不满足 → `[gate] STOP`，退出 1，服务未被触碰。
3. **正式升级**：调用 `brando_pa_safe_upgrade.sh`；再次读报告：`merged=true`、`restored_ok=true`、`verify_after.diffs=[]`、服务已启动；否则报告问题并指出备份位置（升级器失败时自行恢复旧版本）。
4. **复核**：三账户 initial / forward_start / 现金 / 持仓 / 手续费 / 已实现与升级前逐项比对（允许服务重启后追加新事件）；等待心跳恢复（最多 90 s）；输出 health、status、report、acceptance、audit；最后跑一键只读检查生成 `reports_out/brando_pa/mac_check/mac_check_<UTC>.md`。日志在 `reports_out/brando_pa/mac_check/upgrade_verified_<UTC>.log`。

核验方法（升级后、以及验收期间每天一次）：

注意：每次升级都会让服务停止约 1–2 轮；72 h 内不建议再做第三次升级。本次升级内容只影响报表与只读工具，**如果你更在意验收覆盖率，可以不升级**：一键只读检查脚本会自动用 origin 代码运行审计，不需要升级就能得到新口径的审计数字（`report` 的新列则需要升级）。
