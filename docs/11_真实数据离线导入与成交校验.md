# 11 · 真实历史数据离线导入、成交条件校验与结果分级（2026-10-23）

## 1. 为什么需要离线导入
云环境网络策略拒绝 `api.bitget.com` / `bopenapi.bgwapi.io`，在线接口不可用。调研结论：Bitget **没有**官方免费的历史 K 线/逐笔 CSV 批量下载页；官方来源只有公开 API（无需密钥）和账户导出（个人成交，不是行情）。第三方 [Tardis.dev](https://docs.tardis.dev/historical-data-details/bitget) 提供 Bitget 现货逐笔成交与盘口快照历史（自 2024-11-08 起，每月 1 日样本免费，其余需付费 API key）。因此本阶段实现三条真实数据通路，**全部标记来源，绝不用 SIMULATED 冒充**：

| 通路 | 数据 | 命令 |
|---|---|---|
| A. 在线公开接口（需放行域名） | 1m K 线、逐笔成交（`fills-history`）、当前盘口快照 | `bgwq playbook-daily --require-real` |
| B. 离线脚本 + CSV | 在任意有网络的机器运行 `scripts/fetch_bitget_public.py --symbols BTCUSDT ETHUSDT SOLUSDT HYPEUSDT --day 2026-10-22 --out data_in`，复制到项目 `data_in/`，`bgwq import-dir` 或 `playbook-daily` 自动导入 | `bgwq import-dir --day 2026-10-22` |
| C. 第三方 / 通用 CSV | Tardis trades、book_snapshot；任意含时间与 OHLC 列的 CSV（`--map` 列映射） | `bgwq import-csv --kind kline|trades|depth --symbol BTC --file ...` |

目录约定：`data_in/<SYMBOL>/<YYYY-MM-DD>/kline.csv | trades.csv | depth.csv`（支持 .json/.zip）。导入记录 `source = REAL_HISTORICAL:csv:<文件名>`，不做任何价格修饰，缺口由质量标记如实记录。美股代币（Bitget Wallet RWA）无公开 CSV，仍需放行 `bopenapi.bgwapi.io`；若从其他渠道导出分钟线，也可用通路 C 导入。

**历史盘口深度**：公开接口只有当前快照，没有历史深度；`fetch_bitget_public.py --depth-seconds 60` 可对当天实时采样；历史盘口只能来自 Tardis 等第三方。无深度时结果分级为 EXECUTION_ESTIMATED。

## 2. 结果分级（每个档位、每个模板都标注）
| 分级 | 条件 | 含义 |
|---|---|---|
| SIMULATED | 资产池内任一资产为模拟行情 | 只验证模型内部一致性，不代表真实可成交 |
| EXECUTION_ESTIMATED | 全部真实 K 线，但缺逐笔成交或深度快照覆盖 < 90% 分钟 | 成交量按 K 线成交额、深度按成本模型估算；深度未校验的交易在校验表中标注 |
| REAL_HISTORICAL | 全部真实 K 线 + 逐笔成交 + 深度快照覆盖 ≥ 90% | 每笔的成交量与深度均已校验 |

## 3. 逐笔成交条件校验（`playbook/verify.py`，输出 `playbook_checks_<day>_<档>.csv`）
对模板中每一笔（T7 为 522 笔）检查：
1. 时间顺序：入场分钟 < 出场分钟，且两分钟均有 K 线；
2. 实际成交量：该分钟**全部交易合计**投入 ≤ 参与率 10% × 该分钟实际成交额（优先逐笔成交聚合，其次 K 线成交额；未知则标“未校验”）；
3. 订单簿深度：有该分钟 ±5 分钟内快照时，投入 ≤ 距中价 25 bp 内对应一侧（买 ask / 卖 bid）可成交金额；
4. 成交价：参考价在该分钟 [low, high] 内，买价 ≥ 收盘×(1+单边成本)、卖价 ≤ 收盘×(1−单边成本)——**不用一分钟最高/最低价虚构完美成交**；
5. 手续费与滑点：单笔成本 ≥ 投入×2×(手续费+半价差+滑点) + Gas（含冲击时更高）。
违规交易逐条标出；报告总览列出每档“逐笔校验通过 n/N”与“深度校验 查/超深度”。
