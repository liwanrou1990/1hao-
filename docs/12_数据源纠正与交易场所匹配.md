## 3. 系统内的强制规则（本版实现）
1. `asset_day()` 只接受 `venue=token` 的成交数据；**不再回退到 native 原生股价**（Massive/交易所股价只能作参考基准）。
2. 代币化美股 K 线导入必须声明 `--chain` 与 `--contract`（或目录内 `meta.json`），否则拒绝导入；`venue-check` 检查库内每个资产的 source/chain/contract 与登记场所是否相容。
3. 加密货币价格来自交易所现货，若成交渠道假设为钱包 swap，分级最高为 EXECUTION_ESTIMATED（已在报告口径中说明）。
4. 交易方式只取场所真实支持的：全部仅现货多头（无可核实做空渠道）。

## 4. 方向性订单簿容量约束（出场流动性修复的第二步）
- 第一步（上一版）：出场侧按**真实卖出名义额 = 数量 × 出场价**占用该分钟流动性，并限制仓位 S ≤ 出场分钟可用量 × 入场价(1+成本)/出场价。
- 第二步（本版）：有盘口深度快照时，**买入吃 ask 侧、卖出吃 bid 侧**，距中价 25 bp 内容量作为该分钟的方向性上限，与参与率×成交额同时生效，并按方向逐分钟累计占用；空头方向相反。无快照时标注“成交能力仅按参与率×成交额估算”。
- 逐笔校验（`playbook/verify.py`）同样按方向校验深度，并把入场/出场分钟成交额、占用比、深度结论写入流水 CSV 与图表页逐笔表。
