## 1. 指标定义
| 指标 | 采集方式 | 来源 |
|---|---|---|
| USB 识别数量 | `system_profiler SPUSBDataType -json` 中 iPhone 节点数；`idevice_id -l` UDID 数 | macOS |
| iPhone-use 识别数 | `/status.devices` 中出现的目标编号数 | iPhone-use |
| 蓝牙已连 / 可控制数 | `bluetooth=true` / `pointer.ready=true` 的台数 | iPhone-use |
| 画面响应 | 每台 N 次 `/screenshot?maxEdge=600` 的延迟 P50/P95/max，失败数；回显 `X-Device` 校验 | ifarm |
| 蓝牙稳定性 | `ifarm monitor` 观察 10 分钟：`ble_drops`（OK→蓝牙异常次数）、状态变化数、自动恢复数 | ifarm |
| 故障次数 | 广播 `home` 失败数 + 截图失败数 + 身份不一致数（名称/host/回显） | ifarm |

## 2. 测试步骤（每级）
```bash
# 0. 把设备增加到本级台数，逐台 docs/02 注册；贴口标签
./scripts/preflight_mac.sh                                   # 留存 USB 树与蓝牙信息
ifarm verify                                                 # mismatch 必须为 0
ifarm scale-test --levels <N> --stability-minutes 10 --samples 5
# 或一次跑完并在每级之间暂停增加设备：
ifarm scale-test --levels 3,5,10,15,20,30 --stability-minutes 10 --samples 5 --pause-between
```
每级产出 `reports_out/scale_test_REAL_<时间>.md/.json`，并把 `preflight_*.txt` 一并归档。
判定蓝牙瓶颈的标准见 docs/06 §2；USB 识别数 < 台数时先排查 A-832 数据口与线材（docs/00 R1）。
