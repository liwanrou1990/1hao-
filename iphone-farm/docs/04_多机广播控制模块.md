# 04 多机广播控制模块（`broadcast.py` / `ifarm broadcast`，第二阶段）

## 1. 规则
1. 目标来自 `config/groups.yaml` 的分组（`--group pilot`）或显式编号（`--slots 1,2,3`）；任何未注册编号都会让整次广播被拒绝。
2. **每台单独一次 HTTP 调用、单独 `device=完整 id`、单独加锁、单独记录结果**。没有“全体”指令。
3. 白名单：动作必须在 `CATALOG` 中 `safe_for_broadcast=True` 且在 `farm.yaml broadcast.allowed_actions` 内；`sms_*`、`power` 永远禁止广播。
4. 并发 `max_parallel`（默认 8）与错峰 `stagger_ms`（默认 50ms）：iPhone-use 的 HID 待发队列是全局 FIFO，一台的蓝牙背压会阻塞其后所有报文，所以并发不宜过大；逐级测试时按截图延迟与失败率调整。
5. 结果：`BroadcastReport{targets, results[{slot, device, ok, error, latency_ms, status}], ok_count, fail_count, duration_s}`；`--save` 落盘 `reports_out/broadcast_<动作>_<时间>.json`。

## 2. 第二阶段安全动作
```bash
ifarm broadcast home --group pilot                 # 3 台回主屏
ifarm broadcast open_settings --group pilot --save # 3 台打开“设置”
ifarm broadcast wake --slots 1,2,3
ifarm broadcast screenshot --group pilot           # （用 ifarm screenshot 逐台亦可）
ifarm broadcast home --group batch10 --dry-run     # 只列目标，不发指令
```
验收：`fail_count=0`；每条 result 的 `device` 等于注册表中对应编号的 `capture_id`；肉眼确认只有目标组动作。

## 3. 分组
`config/groups.yaml`：
```yaml
groups:
  pilot: [1, 2, 3]
  batch05: [1,2,3,4,5]
  all30: [1, …, 30]
```
可自由增加业务分组（如 `simA: [1,3,5]`）。分组只引用编号，不引用设备 ID。

## 4. 与互斥/监控的关系
- 广播中的每台都在设备锁内执行；监控的恢复动作同样需要锁，故不会在广播中途对同一台 `/match` 或 `/pair`。
- 两个 CLI 同时广播同一台：后到者等待最多 `per_device_lock_timeout_s`，超时记 `busy` 失败。
